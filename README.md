# 聊迹 ChatTrace

聊迹是一个运行在 Windows 本机的只读微信文字聊天归档工具。它提供 Web UI，让用户选择需要归档的会话，手动执行历史或增量同步，并在本地 SQLite 数据库中查询消息。

当前版本为 MVP：

- 检测本机微信状态和完整版本号；
- 仅允许已验证的微信版本同步；
- 扫描会话目录，但默认不选择任何会话；
- 保存会话白名单，每个会话可选历史范围：全部、最近 30/90 天、指定日期起；
- 历史同步和带回看窗口的增量同步；修改历史范围后下次同步自动全量扫描；
- 同步任务实时进度，显示预计总量、已扫描、新增、更新、跳过和错误数，可随时停止；
- 仅保存文字消息，记录发送者和“我”发送的标记；群聊正文已去除 `wxid:` 前缀；
- 无需关键字即可按最新、最早或最近 7 天快速浏览所选会话，并可分页继续加载；
- 支持日期范围及关键词组合查询；多个关键词用空格分隔表示同时包含（3 字及以上使用 FTS5 trigram 索引，更短的词回退为 LIKE）；
- 「话题总结」：按最近 1 天 / 3 天 / 1 周或指定时间段，把会话整理成话题，每个话题包含问题、讨论、结论和开放问题，并可查看原文；
- 「启动微信并归档」：按需启动微信，等待本地数据写入稳定后自动归档并补扫一次（半自动，不会关闭微信）；
- 不发送消息、不注入 DLL、不修改微信进程或微信数据库。

## 当前兼容基线

- Windows 微信 `4.1.15.13`
- `wechatauto-replica` 只读数据库模块 `1.2.4.4`

## 开发运行

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[wechat,dev]"
.\.venv\Scripts\python.exe -m chattrace.app
```

如果使用本地检出的只读适配层，可设置：

```powershell
$env:CHATTRACE_WECHATAUTO_SOURCE = "C:\path\to\wechatauto-replica"
```

默认访问地址：<http://127.0.0.1:18765>

如需临时使用其他端口，可在启动前设置 `CHATTRACE_PORT` 环境变量。

日常使用可以用脚本在后台启动和停止服务（数据固定保存在项目的 `data\` 目录，日志在 `data\logs\server.out` / `server.err`）：

```powershell
.\start.cmd
.\stop.cmd        # 正在同步或生成总结时会拒绝停止；确需中断可用 .\stop.cmd -Force
```

在两台电脑间交接归档数据库，见 [DATABASE_SYNC.md](DATABASE_SYNC.md)。

运行测试：

```powershell
.\.venv\Scripts\python.exe -m pytest
```

## 启动微信并归档

适用于平时不开微信、需要归档时才临时运行的场景。在「运行状态」页点击「启动微信并等待同步」：

1. 记录操作前微信是否已在运行；未运行时启动 `Weixin.exe`（启动前先检查程序版本是否在兼容白名单内）。
2. 等待你在微信中完成登录（扫码或手机确认）。聊迹不会、也不能代替登录。
3. 监控微信本地数据库和 WAL 文件（只读取文件修改时间和大小），连续一段时间无新写入（可选 30～120 秒，默认 45 秒）即视为“数据暂时稳定”。
4. 自动对已选会话执行一次归档，再等待 15 秒无写入后补扫一次。
5. 完成后提示结果。**聊迹不会关闭微信**：如微信由聊迹启动且不再需要，请从托盘菜单选择“退出微信”。

说明：

- “数据暂时稳定”只是本机数据库一段时间没有新写入的工程判断，微信没有接口告知云端消息是否已全部同步；桌面微信能同步多少历史由微信自身决定。
- 如果微信在操作前已在运行，会跳过启动和登录等待，直接等待数据稳定后归档。
- 未检测到登录（10 分钟）、微信持续写入超过 20 分钟、或微信中途退出时，流程停止，微信保持当前状态，已写入的归档不受影响。
- 找不到微信安装位置时，可设置 `CHATTRACE_WEIXIN_EXE` 指向 `Weixin.exe`。
- 「文档」文件夹被重定向（如 OneDrive）时会自动按系统实际路径查找 `xwechat_files`；仍找不到时可设置 `CHATTRACE_WECHAT_DATA_DIR` 指向 `xwechat_files` 或其上级目录。
- 当前版本不提供自动关闭：正常关闭窗口只会让微信最小化到托盘，而强制结束进程可能打断数据库写入。

## 话题总结

在「话题总结」页选择会话和时间范围（最近 1 天 / 3 天 / 1 周为截至当前的滚动区间，“指定时间段”按自然日），页面会先显示消息数量和分段数，确认后点击「生成话题总结」。

- 消息按时间间隔（超过 6 小时）和长度（每段最多 150 条或 2 万字）分段，每段由模型整理出话题；多段时再合并跨段的同一话题。
- 每个话题包括：问题、讨论要点、结论（只收录明确达成的）、开放问题，以及状态：已有结论 / 仍在进行 / 无明确结论。点击「查看原文」可核对来源消息；模型引用了输入中不存在的消息时，该引用会被丢弃。
- 结果会保存，可在左侧「历史总结」中查看；范围内后来又归档了新消息时会标记“有新消息”。相同内容的分段会复用已有结果，不重复调用 API。
- **数据边界**：生成时会把所选会话在该时间段内的文字消息发送到 OpenAI（Responses API，`store=false`），其他会话和时间段不会发送；API key 不写入数据库、页面或日志。

OpenAI 配置与 zoom-chat-kb-hub 相同，按以下顺序读取：

1. 环境变量 `OPENAI_API_KEY`（可选 `OPENAI_MODEL`、`OPENAI_BASE_URL`）；
2. `OPENAI_CONFIG_FILE` 指向的 JSON；
3. 数据目录下的 `openai_config.json`；
4. `C:\Works\access-redmine\openai_config.json`（可用 `CHATTRACE_OPENAI_FALLBACK_CONFIG` 修改）。

JSON 格式：`{"api_key": "...", "base_url": ""}`。模型档位可在页面中切换：低 `gpt-5-mini`、中 `gpt-5.6-luna`（默认）、高 `gpt-5.6-terra`。

## 推荐工作流

1. 在「运行状态」确认微信正在运行且版本兼容。
2. 在「会话选择」刷新会话，只勾选需要归档的会话。
3. 回到「运行状态」手动同步，并通过进度条观察扫描和入库情况。
4. 在「消息浏览」选择会话，直接查看最近消息；需要时切换为最早、最近 7 天或输入日期与关键词。
5. 在「话题总结」选择会话和时间范围，确认消息数量后生成话题总结。

## 数据目录

默认保存在 `%LOCALAPPDATA%\ChatTrace`：

- `chattrace.db`：产品归档数据库；
- `wechat-cache\keys.json`：数据库密钥缓存，使用 Windows DPAPI 加密（仅当前 Windows 用户可解密）；旧版明文缓存会在启动时自动转换；
- `wechat-cache\decrypted\`：同步期间的临时解密副本，包含**全部会话**的明文，同步/扫描结束及程序启动时自动删除；
- `logs\chattrace.log`：不包含聊天正文和密钥的运行日志（滚动保留 5 份）。

可用 `CHATTRACE_DATA_DIR` 指向其他本地目录。如需保留解密副本以加快下次同步（会以明文留存全部聊天记录），可设置 `CHATTRACE_KEEP_DECRYPTED_CACHE=1`。

## 安全边界

- 微信聊天数据库始终只读；「启动微信并归档」会启动微信客户端，属于应用生命周期控制，只在用户点击时进行，且从不关闭或结束微信进程；
- Web 服务仅监听 `127.0.0.1`，只接受 Host 为 `127.0.0.1`/`localhost` 的请求（防 DNS rebinding），拒绝来自其他网页的跨站请求；
- 未经用户选择的会话不会写入消息表；
- 未知微信版本允许查询既有归档，但禁止新同步；微信未运行或版本不兼容时不会创建同步任务；
- 日志不得记录消息正文、联系人标识或数据库密钥；
- 本工具只能读取电脑微信已经同步到本机的数据；
- 程序异常退出时遗留的“同步中”任务会在下次启动时标记为“已中断”。
