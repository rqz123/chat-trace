# 新功能：不跟踪会话（2026-10-07）

用户需求：会话选择页的会话太多（本机共 715 个，其中 582 个超过 30 天无新消息，336 个超过一年），希望能把不需要的会话设为“不跟踪”。不跟踪的会话不再显示，也不会被同步。

## 行为

- **不跟踪**：会话从列表中隐藏，同时关闭同步（`sync_enabled=0`）。**已归档的消息和话题总结全部保留**。
- **恢复**：勾选“显示不跟踪的会话（N）”后，可以看到这些会话（灰色显示），点“恢复”即可。恢复只是重新显示，**不会自动恢复同步**，需要的话再勾选“同步”。
- 在显示不跟踪会话时，直接勾选某个会话的“同步”，也会自动把它恢复为跟踪。
- **批量不跟踪**：按“最近消息时间”选择 30 天、90 天、半年（默认）或一年以上没有新消息的会话。执行前会弹窗显示将影响的数量，确认后才执行。批量操作**不会影响已选择同步的会话**。没有最近消息时间的会话按“很久以前”处理。
- 单个不跟踪一个正在同步的会话时，会先弹窗确认，并说明将停止后续同步、已归档内容保留。
- 重新“扫描本机会话”时，会保留用户设置的不跟踪状态。
- 同步、启动并归档等流程只处理“已选择且未隐藏”的会话（`selected_conversations` 增加了 `hidden=0` 条件，作为双重保险）。
- 消息浏览和话题总结的下拉框：不跟踪但仍有归档消息的会话照常显示，并标注“（不跟踪）”，因为数据还在、仍可查询。
- 会话表新增“最近消息”一列，用相对时间显示（今天 / N 天前 / N 个月前 / N 年前），鼠标悬停显示完整时间，方便判断会话是否已经很久没有动静。

## 实现

- `conversations.hidden` 列：和已有的 `total_count` 列一样，用 `_ensure_column` 幂等添加，旧库启动时自动补上。只新增一列，不改动已有数据。
- `Storage`：
  - 新增 `set_conversations_hidden(ids, hidden)`；
  - 新增 `count_inactive_conversations(before)` 和 `hide_inactive_conversations(before)`，条件为 `hidden=0 AND sync_enabled=0 AND COALESCE(last_source_message_at,0) < before`；
  - `configure_conversation` 在启用同步时会清除 `hidden`。
- 接口：

  | 方法 | 路径 | 参数 | 说明 |
  |---|---|---|---|
  | POST | `/api/conversations/hide` | `{conversation_ids:[...], hidden:true/false}` | 不跟踪或恢复指定会话 |
  | GET | `/api/conversations/inactive` | `?days=N` | 预览将影响的数量，N 取 7～3650 |
  | POST | `/api/conversations/hide-inactive` | `{days:N}` | 批量不跟踪 |

- UI：工具栏新增“显示不跟踪的会话”开关、“批量不跟踪”选择和按钮，以及说明文字；会话表新增“最近消息”列和行操作按钮。另外修正了工具栏中复选框被文本框样式拉伸的问题。

## 验证

- 测试：53 个，全部通过（新增 `test_untracked_conversations` 和 `test_untrack_endpoints`），覆盖：
  - 批量操作跳过已选择同步的会话；
  - 无时间戳的会话按很久以前处理；
  - 重新扫描后保留隐藏状态；
  - 不跟踪会停止同步，恢复不会重新开启同步；
  - 勾选同步会恢复显示；
  - 接口参数校验。
- UI：用合成数据截图检查，修正了复选框被拉伸的样式问题。
- 已重启服务。在真实数据上**只做了数量预览，没有隐藏任何会话**：30 天以上 582 个，90 天以上 510 个，半年以上 449 个，一年以上 336 个；当前隐藏 0 个，已选择同步 7 个，话题总结 2 份，均保持不变。

## 补充：自动过滤没有群名的群（2026-10-07）

用户需求：“@chatroom 这类会话，同步时全部过滤掉”。经确认，指的是**没有群名、列表中直接显示为 `xxxx@chatroom` 的群**，而不是所有群聊（用户正在同步的 7 个会话全是群聊）。

- **判断规则**：内部 ID 以 `@chatroom` 结尾，并且显示名为空、等于 ID 本身，或者以 `@chatroom` 结尾。
- **自动不跟踪**：在 `upsert_conversations`（每次扫描）和 `Storage.initialize`（每次启动，处理已有数据）中执行 `_apply_unnamed_group_rule`。已选择同步的群不受影响。
- 新增 `conversations.hidden_reason` 列，用来区分隐藏原因、保护用户的手动选择：

  | 取值 | 含义 | 自动规则如何处理 |
  |---|---|---|
  | `unnamed` | 因无名被自动隐藏 | 群有了名字后自动恢复显示 |
  | `user` | 用户手动或批量设为不跟踪 | 不会被自动恢复 |
  | `kept` | 用户手动恢复，或勾选了同步 | 以后不再自动隐藏 |
  | `NULL` | 早于本列添加时被隐藏的会话 | 按用户隐藏处理（保持隐藏） |

- UI：在“显示不跟踪的会话”中，自动隐藏的无名群会标注“（无群名，自动不跟踪）”；说明文字补充了这条规则。
- 测试：55 个，全部通过（新增 `test_unnamed_groups_are_auto_untracked` 和 `test_existing_unnamed_groups_untracked_on_startup`）。
- **真实数据结果**（重启后）：
  - 157 个无名群已全部隐藏，其中 115 个此前已被用户批量隐藏，本次自动隐藏 42 个；
  - 当前可见会话 272 个，已选择同步的 7 个、话题总结 2 份均未受影响。
